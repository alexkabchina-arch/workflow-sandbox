# /tickets

Из любого чекаута проекта, обычным Bash:

```bash
scripts/canon/ticket status
```

Таблицу из вывода передать владельцу как есть, без пересказа. Шаг, расход и время — из файлов
состояния тикетов, PR и CI — живые данные GitHub на момент запроса. Колонка «Ждём»: `владелец` —
вопрос в тикете (`ticket ask`) или отчёт об остановке, нужен его ответ; `агент` — ход сессии
тикета; `CI` — PR ждёт проверок и авто-мёржа.

Скрипт упал (код 1 или 2, причина строкой `ticket: …`) — причину одной строкой владельцу.

Скилл не зовётся `status`: встроенный `/status` Claude Code он бы перекрыл или сам не
вызвался бы. Как устроено — `docs/ticket.md` канона alexkabchina-arch/workflow.
